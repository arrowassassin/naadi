# Content authoring (segment 23)

How an author task (S23-A … S23-G) adds study text, questions, flashcards and figures. The rules on *what* to
write are in [docs/segments/23-content-library.md](segments/23-content-library.md) (originality, NBME item
style, study-text depth); this guide covers the *files* and the *commands*.

## 1. Your pack

Each author task owns one directory. Nobody else edits it, so parallel authors never conflict.

| Task | Pack (`data/content/…`) | `idPrefix` | Outline systems |
|---|---|---|---|
| S23-A | `general-immune-blood` | `s23a` | 01, 02, 03 (+ general principles) |
| S23-B | `cardio-resp` | `s23b` | 08, 09 |
| S23-C | `renal-endo-nutrition` | `s23c` | 11, 15 (+ nutrition) |
| S23-D | `gi-multisystem` | `s23d` | 10, 16 |
| S23-E | `neuro-behavioral` | `s23e` | 05, 04 |
| S23-F | `skin-msk-repro` | `s23f` | 06, 07, 12, 13, 14 |
| S23-G | `biostat-social` | `s23g` | 17, 18 |

```
data/content/<pack>/
  pack.json             id, title, owner, idPrefix, systems, retire[], retag{}
  chapters.json         chapters → sections
  questions.json        {"sets": [...], "items": [...]}
  cards.json            hand-written flashcards
  cards.generated.json  GENERATED by tools/generate_cards.py (key-fact and objective cards)
  figures.json          figure rows; the SVG files go in figures/
  section_bodies.json   GENERATED: never edit by hand (see §7)
```

- **Every id starts with your prefix**: `s23b-ch01`, `s23b-s0101`, `s23b-q0001`, `s23b-set01`, `s23b-c0001`,
  `s23b-fig01`. Lowercase, `[a-z0-9_.-]`.
- Ids are permanent. The importer upserts by id, so editing a row and re-importing updates it in place. Never
  reuse an id for different content; retire it instead.
- A complete worked example (one chapter with a figure, a single item, an abstract set, a sequential set and two
  cards) is the test fixture [`apps/api/tests/fixtures/content/sample-pack/`](../apps/api/tests/fixtures/content/sample-pack).
  Copy its shapes.

### The legacy bundle

`data/chapters.json`, `data/questions.json` and `data/figures.json` are the original 14 chapters and 685 items.
They stay where they are, and authors don't edit them. Use your `pack.json` instead:

- `"retire": ["ch05-q12"]` retires a legacy item you are replacing with a better one in your pack.
- `"retag": {"ch05-q01": ["usmle2026.08.08.01"]}` corrects the USMLE-2026 area that the automatic mapping
  gave a legacy item (`data/taxonomy/usmle2026_question_map.json`, built by `tools/usmle2026.py`). Its
  discipline, clinical-science and task tags are kept.

Only retag or retire items in your own systems.

## 2. Tags: the USMLE-2026 taxonomy

The taxonomy lives in `data/taxonomy/usmle2026.json`, generated by `python tools/usmle2026.py`. It has
18 systems, 147 categories and 276 level-3 areas, plus three axes.

- **`areas`**: the outline's **leaf** ids, written as `usmle2026.<system>.<category>.<area>`, e.g.
  `usmle2026.08.05.01` (ischemic heart disease). The leaves are the 276 areas plus two categories that have no
  areas: `usmle2026.15.06` (hypothalamic) and `usmle2026.15.07` (MEN). Give 1 area per item, or at most 3. The
  importer adds the category and system ids itself. Area names are short labels; the full outline is at
  usmle.org (sources row `usmle-content-outline-2026`). Never paste the outline's example lists into content.
- **`disciplines`** (Step 1 axis): `pathology`, `physiology`, `nutrition`, `anatomy_embryology`, `microbiology`,
  `pharmacology`, `behavioral_sciences`, `biochemistry`, `histology_cell_biology`, `immunology`, `genetics`.
- **`clinicalSciences`** (Step 2 CK axis): `medicine`, `pediatrics`, `obgyn`, `psychiatry`, `surgery`.
- **`tasks`** (both Steps): `medical_knowledge`, `pc_history_pe`, `pc_diagnosis`, `pc_lab_diagnostic`,
  `pc_prognosis`, `pc_health_maintenance`, `pc_pharmacotherapy`, `pc_clinical_interventions`,
  `pc_mixed_management`, `communication`, `professionalism`, `systems_based_practice`, `pbli`.

Tag Nutrition wherever it applies: it is 15–20% of both Steps, co-coded with a system.

**Blueprint targets.** Each leaf area has, per Step, `targetItems` (the weight-row midpoint × 2,000, spread
evenly over the row's areas) and a floor of `minItems` = 6. To see your areas with their targets and current
counts:

```bash
cd apps/api && uv run python ../../tools/validate_content.py --pack cardio-resp --areas
# usmle2026.08.05.01  step1 1/10  step2ck 5/10  Ischemic heart disease
```

## 3. Sections (`chapters.json`)

```json
[{
  "id": "s23b-ch01", "exam": "step1", "order": 100, "title": "Cardiovascular · Ischemic heart disease",
  "meta": null, "source": "naadi-original-v1",
  "sections": [{
    "id": "s23b-s0101",
    "heading": "Stable angina",
    "html": "<p>…</p>[[figure:s23b-fig01]]<p>…</p>",
    "figureIds": ["s23b-fig01"],
    "areas": ["usmle2026.08.05.01"],
    "furtherReading": [
      {"label": "StatPearls (NCBI Bookshelf)", "url": "https://www.ncbi.nlm.nih.gov/books/NBK430685/", "sourceId": "statpearls"}
    ]
  }]
}]
```

- `exam` is the chapter's Step: `step1` or `step2ck`. Write Step 2 CK management depth in `step2ck` chapters.
- `html` takes the elements the reader renders: `p`, `h2`/`h3`, `ul`/`ol`/`li`, `table` (`tr`/`th`/`td`),
  `strong`, `em`, `sub`, `sup`, key facts as `<span class="hy">…</span>` (shown as a key-fact highlight, and
  each one becomes a cloze flashcard, §5), and callouts: `<div class="trap">` (exam traps), `<div class="pearl">`
  (high-yield pearls) and `<div class="bridge">`, used as in `data/chapters.json`.
  **There are no links in the body.**
- Figures go inline as `[[figure:<id>]]` placeholders. `figureIds` lists the same ids in the same order.
- `furtherReading` holds link-only references: the matching StatPearls page, the guideline, the official USMLE
  page. Each `sourceId` must be a row in `config/sources.yaml`. Restate a guideline in your own words, never
  copy its text.

## 4. Items (`questions.json`)

```json
{"sets": [], "items": [{
  "id": "s23b-q0001",
  "exam": "step2ck",
  "format": "single",
  "chapterId": "s23b-ch01",
  "stemHtml": "<p>A 67-year-old man …? </p>",
  "options": [{"label": "A", "html": "…"}, {"label": "B", "html": "…"}, {"label": "C", "html": "…"},
              {"label": "D", "html": "…"}, {"label": "E", "html": "…"}],
  "answer": "B",
  "explanationHtml": "<p>Why B is right, the key concept, then a <strong>Takeaway:</strong> line.</p>",
  "whyNot": {"A": "…", "C": "…", "D": "…", "E": "…"},
  "objective": "Choose primary PCI for STEMI when it is promptly available.",
  "areas": ["usmle2026.08.05.01"],
  "disciplines": [], "clinicalSciences": ["medicine"], "tasks": ["pc_mixed_management"],
  "difficulty": 3,
  "source": "naadi-original-v1",
  "references": [],
  "figureIds": [],
  "tags": ["STEMI"],
  "status": "published",
  "review": {"status": "self_reviewed", "humanExpertReviewed": false, "author": "seg23-b"}
}]}
```

Required on every item:
- at least 5 options, labelled `A`, `B`, `C`, … in order;
- an `answer` that is one of the options;
- `whyNot` text for **every** wrong option, and no entry for the answer;
- `objective`, at least 1 leaf in `areas`, and `difficulty` from 1 to 5. Aim for a spread of about
  20/30/30/15/5%.

Other fields:
- `chapterId` (optional) lists the item under that chapter's questions.
- `figureIds` (optional) names pack figures that the stem uses.
- `references` (optional) lists the link-only `sources` ids whose facts the item follows, e.g. a guideline row.
- `status`: `published` (the default), `in_review` or `draft`. Only `published` items reach students.
- `review.humanExpertReviewed` stays `false`. Only the physician review flips it, never an author.
- `difficulty` 1–2 is shown as easy, 3 as medium and 4–5 as hard. The 1–5 value is stored too.
- Answers, explanations, why-not text and objectives never reach the client before an attempt. They are server
  columns, served only by the qbank API.

### Sequential item sets (Step 2 CK)

A sequential set is 2–3 linked items. The student answers them in order, and each answer locks once given. A
later item may reveal the earlier answer.

```json
"sets": [{"id": "s23b-set01", "exam": "step2ck", "kind": "sequential", "title": "Inferior STEMI", "source": "naadi-original-v1"}],
"items": [
  {"id": "s23b-q0101", "format": "sequential", "setId": "s23b-set01", "setOrder": 1, "...": "…"},
  {"id": "s23b-q0102", "format": "sequential", "setId": "s23b-set01", "setOrder": 2, "...": "…"}
]
```

### Abstract-format sets

An abstract set is a study summary followed by 2 or more questions. The summary goes in the set's `introHtml`,
and each item's stem asks only its own question.

```json
{"id": "s23g-set01", "exam": "step2ck", "kind": "abstract", "title": "…",
 "introHtml": "<p><strong>Study summary (fictional).</strong> A randomized … trial …</p>", "source": "naadi-original-v1"}
```

Items in a set use `"format": "abstract"` (or `"sequential"`), with `setId` and `setOrder` numbered from 1. All
items in a set have the set's `exam`. Invent the studies: never summarise a real paper's abstract.

A `"format": "chart"` item is a single item whose stem carries a table, such as a lab panel or a medication
list.

### Lab values

Use the analyte names and units of Naadi's own lab table (`lab_values` in `config/app_config.yaml`). Give SI
units next to conventional units where the exam does. The validator (lint rule L13) checks every value and unit
against this table.

## 5. Flashcards (`cards.json`)

```json
[{"id": "s23b-c0001", "frontHtml": "…?", "backHtml": "…", "sectionId": "s23b-s0101", "questionId": null,
  "areas": ["usmle2026.08.05.01"], "source": "naadi-original-v1", "tags": []}]
```

Write cards for every section. A card linked to a question (`questionId`) is shown only after the student has
attempted that question, because it restates the answer. Cards feed FSRS like any shared card: every student's
review queue picks them up as new cards.

**Generated cards.** `python tools/generate_cards.py` writes `cards.generated.json` in every pack (never edit
it by hand; CI fails when it is stale). It makes two kinds of card from your own text:
- one **cloze card per key fact**: each `<span class="hy">` in a section becomes a card whose front is that
  sentence with the fact blanked (`[…]`) and whose back shows it in bold;
- one **objective card per published item**: the front is the item's `objective`, the back its
  "Takeaway:" line (or the first sentence of the explanation). It is linked to the item, so it opens only after
  an attempt.

So mark 2–5 key facts per section with `<span class="hy">` and end each explanation with a
`<strong>Takeaway:</strong>` line. Hand-written cards in `cards.json` add to the generated ones.

## 6. Figures (`figures.json` + `figures/`)

```json
[{"id": "s23b-fig01", "chapterId": "s23b-ch01", "caption": "Figure 1. …", "file": "figures/s23b-fig01.svg",
  "source": "naadi-original-v1", "attribution": null}]
```

- **Original SVG** is the default. The importer sanitises it (no scripts, no external references) and uploads it.
- **Licensed images** follow the same rules: a CC BY or public-domain file you have checked, with its own
  `sources` row (or a commercial-safe catalog row such as Servier Medical Art), and the full credit in
  `attribution`. Nothing is hotlinked. Raster support arrives with phase 2; until then, draw SVG.
- Every figure must be placed in a section (`[[figure:id]]`) or named by an item's `figureIds`.

## 7. Commands

Start a local stack first. Never point these commands at the hosted project: export loopback values for
`DATABASE_URL`, `SUPABASE_URL` and `APP_BASE_URL`, and use your own container names and ports (see
`apps/api/tests/db/stack.sh`).

```bash
# 1. After editing any section html or item: regenerate the bodies and the generated cards
pnpm --filter @naadi/shared seed:convert
python3 tools/generate_cards.py

# 2. Validate (schema, ids, tags, sets, why-not, key, item-writing lint, labs, licence gate, originality,
#    stale bodies); exit 1 on any error. Warnings are listed for you and the reviewer.
cd apps/api && uv run python ../../tools/validate_content.py --pack <pack>
uv run python ../../tools/validate_content.py --pack <pack> --areas      # targets vs current counts

# 3. Import into your local stack (idempotent: a second run reports 0 changes)
uv run python scripts/seed.py --data ../../data --dry-run
uv run python scripts/seed.py --data ../../data

# 4. Preview (pnpm dev; sign in as the local admin)
#    section:  http://localhost:5173/learn/<chapterId>/<sectionId>
#    item:     http://localhost:5173/admin/questions/<itemId>   (stem, key, explanation, why-not)
#    practice: /practice → build a block filtered to your system
```

Check every new section, item and card at iPad portrait and landscape and at phone width.

Before you integrate, run `seed:convert`, the validator and `uv run pytest -q tests/seed`. Integrate in batches
(for example, one system at a time) and post an `update` with your counts.

## 8. Licences in one paragraph

Store only commercial-safe content: Naadi originals (`naadi-original-v1`), public domain, CC0 and CC BY. CC BY-SA
stays in its own partition. NC and ND sources are link-only and appear only in `furtherReading` or `references`:
StatPearls, OpenStax 2e, WHO, Radiopaedia, GeneReviews and the text of USPSTF. Don't use imported question
banks or Anki decks, and don't copy text, mnemonics or images from commercial review books or question banks.
The validator's licence gate refuses any stored row whose source is not storable.

## 9. What the validator checks

| Check | Fails on |
|---|---|
| schema | a field missing or misnamed, an id without your prefix, fewer than 5 options, a key that is not an option, `whyNot` not covering exactly the wrong options, a set of the wrong size or numbering |
| references | an area that is not a USMLE-2026 leaf, an unknown discipline, clinical-science or task slug, an unknown set, figure, chapter, section or source |
| why_not | a reason under 4 words, or two options with the same reason |
| key | two options with the same text, or an explanation that names another letter ("the correct answer is D") |
| lint | the NBME item-writing rules the review queue runs (naadi_api/authoring/lint.py): "all/none of the above", negative stems, cueing, option homogeneity, vignette shape, lab values and units (L13). Its warnings (for example L08 option order) are advisory |
| licence | a chapter, item, set or card whose source cannot be stored as text, or a figure whose source cannot be hosted, or a licensed figure without attribution |
| originality | see below |
| stale bodies | `section_bodies.json` older than the section html |

**Originality: the fallback applies.** The brief asks for an 8-gram check against fingerprints of the
forbidden commercial texts (First Aid, UWorld, AMBOSS, Pathoma, NBME …). No such corpus can be assembled
legally inside this repository, so `config/originality_fingerprints.txt` has no digests. The validator says
`originality check: fallback` and runs:
1. an **internal near-duplicate check**: a pack stem, explanation, section, card or abstract that shares more
   than 35% of its 8-word shingles with any other stored text is an error; and
2. a **manual review sample** for S23-R: `uv run python ../../tools/validate_content.py --sample` prints a
   deterministic 15% sample of pack items, stratified by pack, Step, system and difficulty.

If someone who may lawfully read such snippets builds digests locally (`python tools/build_fingerprints.py
<folder outside the repo>`), only salted hashes are committed. The validator then reports
`originality check: forbidden-corpus fingerprints` and also fails any text with more than 8% matching 8-grams.
