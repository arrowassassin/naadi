## Scope
### Data (one migration, RLS in the same file; update `test_rls_coverage.py` + `live_check.py`)
- `assistant_threads` gains `aegra_thread_id uuid unique`, `last_message_at`, `page_ref jsonb` (route/type/id only, no selection text). Long-term memory lives in the Aegra store, namespace `("memories", user_id)`, never in a Naadi table.

### `tutor` graph (`naadi_api/agent/graphs/tutor.py`, registered in `aegra.json`)
- `START → guard → tutor ⇄ tools → compose → END`; `guard → refuse → END`. State: `messages`, `page_context`, `user_id`, `exam_mode`, `attachments[]`, `citations[]`, `blocks[]`, `canvas[]`.
- **guard** (Python first): `exam_mode` comes from `active_exam(conn, user_id)` on the server, never from the client flag; any active timed/exam block → refuse with structured `{reason: "exam_mode"}`. Page question: the server re-checks the attempt (S08/S09 rules) and drops `chosen`/`answered` the client claims if no attempt exists. Intent rules (pathway/visa → rule 5, dosing → "I don't know + search"); the `router` role only when the rules are ambiguous (counts as a turn call).
- **tutor**: `get_gateway().chat_model("tutor", ctx)` with tools bound, `purpose="chat"`, `ctx.privacy` from the profile; the 4-call cap is the gateway's `TurnCounter` (5th call → compose with what exists). Cap or budget exhausted → degrade: answer from `search_local` hits only, a `sources` block and a `notice` block with the reset time (`useAgent` already maps it).
- **compose**: citations as `citation` events, blocks as `custom` events (`flowchart`, `image`, `video`, `sources`, `actions`, `card_preview`, `table`, `chart`, `canvas`), the §6.5 disclaimer once per thread. `stream_mode=["messages","custom","updates"]`.
### Sessions, memory and context window (lead decision)
- **Past chats are kept** until the student deletes them: one Aegra thread per conversation, listed in the thread list (title from the first question, renameable, searchable by title). The checkpointer TTL `keep_latest` (aegra.json) only prunes older intermediate checkpoints after 30 days and always keeps each thread's latest state, so a chat from months ago reopens intact; a db test proves a thread older than the TTL still loads after a sweep. Deleting a thread deletes its checkpoints and its `assistant_threads` row.
- **Context window never overflows.** Before every model call a `budget_context` step sizes the prompt to the selected model's context limit (from `config/models.yaml`, with a safety margin and room for tools and the answer). It keeps the system prompt, the page context, the latest turns verbatim and the most relevant retrieved passages; older turns are folded into a rolling `summary` kept in graph state, written by the existing `long_context` role (config/models.yaml) only when the thread crosses the threshold (counts as a turn call; the cap still holds), never by a hidden extra call. Tool results are truncated to their cited passages. Fallback to a smaller model re-runs the sizing for that model. Unit tests with a fake tokenizer cover long threads, huge attachments and fallback to a smaller context.
- **Resuming an old thread** starts from the summary plus the last turns; the student sees the whole history in the UI (rendered from the checkpoint), the model sees the budgeted view.
- **Long-term memory** (`remember`/`forget`, Aegra store namespace `("memories", user_id)`, max `memory_max_items`): short facts the student approves (weak topics, preferences, exam date), shown and deletable in Settings → Assistant; the tutor retrieves the few most relevant memories per turn by semantic search, never the whole store. Memories are scrubbed like any prompt and never hold vault text or PII.
- **Session expiry mid-chat:** a 401 during a stream keeps the draft and the partial answer, refreshes the session and offers "Continue" (resume the same thread); a cancelled or failed run is resumable from its last checkpoint.
### Tools (`naadi_api/agent/tools/`; each checks the run's authenticated user; writes call `interrupt()` with a typed preview and do nothing until resumed with `accept`)
- Read: `search_knowledge(query, scope?)` (wraps `search_local`; questions only after an attempt and never inside an active block), `get_page(ref)` (section, question **stem/options only until attempted**, video timestamp; PDF page arrives with S15), `web_search`/`web_extract` (`get_search()`, only when the best KB score < `kb_low_score` or the student asks; results labelled with their layer, "Tavily" for Tavily), `get_analytics(metric, by, period)` (enum of S09/S11 typed queries; returns rows, never SQL), `render_diagram(mermaid)` (parsed server-side with a size cap; invalid → error block), `suggest_video(topic)` (approved `media_assets` only), `open_in_canvas(kind, ref)`.
- Write (interrupt): `save_note`/`append_to_note`/`update_note` (S13 API, anchored), `make_flashcards(items)` (preview cards, S10), `build_block(criteria)` (S08 `POST /api/blocks`), `add_to_plan(item)` (`plan_items`, origin `assistant`), `edit_chapter_section(section_id, ops[])` (ops `replace|insert_after|delete` on top-level blocks, content validated against S06's node schema; diff preview; admin on a shared chapter → `chapter_section_revisions` row `origin='assistant'` + section update; everyone else → a private overlay note on that section), `remember(fact)`/`forget(key)`.
- Never in any prompt or tool result: `answer`, `answer_html`, `explanation_html`, `why_not_html`, `educational_objective` of an unattempted question, vault content, the student's name/email.
