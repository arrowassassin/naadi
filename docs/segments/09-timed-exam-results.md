## Scope
### Data (one Alembic migration, RLS in the same file; add new tables to `USER_TABLES` in `tests/db/live_check.py` and the RLS coverage test)
- `block_sections` (user table): `block_id`, `user_id`, `n`, `first_index`, `count`, `time_limit_s`, `started_at`, `deadline_at`, `paused_at`, `paused_total_ms`, `ended_at`, `ended_reason ('submitted'|'expired')`. Four own-row policies for the coverage test, but `authenticated` gets **select only**: every timing write is the API's (follow 0001's backend-only pattern for `attempts.correct`). A missing or deleted row is never "fresh time": the API treats it as expired.
- No separate session table: the layout lives in `blocks.config` (`sections`, `break_s`), plus a backend-only `blocks.break_used_ms`. `attempts` gains backend-only `first_chosen`, `changes smallint`, `answered_at` (set by the API).
- Tighten client privileges: revoke `insert` on `attempts` and `insert/update` on `blocks` from `authenticated` (S08's web already writes through the API); update `test_rls.py` and live_check expectations.
- `app_config.exam_rules` adds `break_minutes: 45` and `expiry_grace_seconds: 2` (yaml + `config_api/schemas.py` + defaults).
### API (pydantic → OpenAPI → zod; injectable clock `now()` everywhere so tests control time)
- `POST /api/blocks` accepts `mode: timed|exam` once `qbank_timed` is on, with `sections` (1 .. `exam_rules.exams[x].blocks`, ≤ 40 questions each); `POST /api/blocks/mock` `{chapter_id: mock1|mock2}` builds the seeded mock in its fixed order (block 1 then 2), always **exam** mode.
- `GET /api/blocks/{id}/clock` → `{server_now, state: not_started|running|paused|break|finished, section_n, deadline_at, remaining_ms, break_remaining_ms, paused}`; every block/attempt response embeds the same clock. State is computed lazily from timestamps on each request (no background ticker), so a closed tab still expires on time.
- `POST /api/blocks/{id}/sections/{n}/start|pause|resume|end`; pause only in `timed` (exam: 409 "Pause is off in exam mode"). Between sections a break runs against the shared pool; when the pool is spent the next section starts automatically at that instant.
- Attempts in timed/exam: `POST /api/blocks/{id}/attempts` records `chosen` (and `first_chosen`/`changes`), never returns `correct` or explanations; rejected with 409 after `deadline_at + grace` or for an ended section (no going back, like test day). `seconds` is clamped to the section's elapsed time.
- `GET /api/blocks/{id}/questions/{n}` keeps S08's rule: no answer fields until the **whole block** is finished; only the current section's questions are served while running.
- `POST /api/blocks/{id}/finish` grades (server) and sets `score`; `GET /api/blocks/{id}/results` → % correct, mean/median seconds per question vs `seconds_per_question`, changed answers (right→wrong, wrong→right), flagged (and how many correct), per-question grid, by system/discipline/competency (taxonomy map), official weight overlay (`weight_min/max` per system vs this block's share and accuracy), last 10 timed/exam blocks trend.
- `naadi_api/analytics/` (shared with S11/S14 `get_analytics`): typed queries only (accuracy by taxonomy node and period, time per question, trend). `naadi_api/qbank/exam_state.py: active_exam(conn, user_id)` for the shell and S14's guard.
### Web
- **Exam view** (`/practice/blocks/$id/$n`, timed/exam): header "Block x of y · Question n of 40", timer (remaining from `deadline_at − (Date.now() + offset)`; offset = best-RTT sample of `server_now`, re-synced on `visibilitychange`, `pageshow`, `focus` and every 60 s; never a decrementing counter), break-left chip, "End block" with confirm. 40-tile navigator (answered filled, unanswered dashed, flagged amber ring **plus** word in the accessible name and a flag glyph, current lime); tools rail: flag, highlight text, strike out option, lab values (S08), calculator (four-function), scratch ink (`exam_scratch`, surface id `{block_id}:{n}`, via 12b), zoom and contrast. Highlights/strike-outs are device-local (Dexie, keyed by block, cleared 7 days after finish). Assistant bar hidden in exam mode with `ui_copy agent.exam_mode`; timed mode keeps it only if the assistant flag is on. Phone layout per PhoneQbank. At 5 and 1 minutes an `aria-live` announcement; at 0 the section ends and shows the break or results.
- **Results** (`/practice/blocks/$id/results`) per board: big %, "29 of 40" sentence, stat tiles, question grid (filled = correct, amber ring + "missed", dashed + "flagged"), topic bars (amber + word "weak" under 60 %), trend line, official-weights overlay, "What Naadi sees" insight sentences built deterministically from the stats (ui_copy templates, no LLM). Lime CTA "Review N misses" → review mode (S08 view with explanations, filter all/missed/flagged/changed). "Make cards from misses" (S10, attempt-gated). "Adjust this week's plan" hidden until S16.

- States: loading, error (timer keeps running from the last clock; banner), offline (answers queue with "will sync"; the clock is still the server's deadline, shown from the cached offset).
## Tests
- Unit (pytest, frozen clock): deadline/pause/break/auto-start/expiry state machine, grace, closed-section rejects, missing-row = expired, changed-answer metrics, results aggregates, weight overlay. vitest: offset estimator, display rounding, keyboard map.
- db: client cannot write `block_sections`, timing or grading columns, or insert attempts; no answer field before finish via every endpoint (block, question, results, search, cards); RLS on new tables.
- e2e (3 browsers × 6 viewports, frozen-DOM axe helper): Mock A end to end (40 answers → section end → break → section 2 → results); timer within ±1 s of the server after reload, after a 30 s background (`Page.setWebLifecycleState` frozen in Chromium, `visibilitychange` elsewhere) and with the browser clock skewed 10 min (`page.clock`); pause refused in exam mode; leak probe before finish.
## Acceptance
1. Mock A runs as an exam-mode 2×40 with a 60-minute server deadline per block; timer accurate to ±1 s across backgrounding, reload and client clock skew.
2. No answer or explanation reaches the client before the block is finished; the assistant is silent in exam mode.
3. Results show % correct, time per question, changed answers, weak areas (amber + word) and the official weight overlay; matches Exam/Results/PhoneQbank boards; one lime CTA per view; zero axe violations / console errors.

## Decisions (lead to check)
- Timing lives in a select-only `block_sections` table, not `blocks.started_at` (client-writable today); client insert on `attempts` and insert/update on `blocks` are revoked.
- Break pool 45 min per session (USMLE day rule) for every multi-section block; spent pool auto-starts the next section. Mocks are always exam mode.
- Explanations for timed/exam unlock only when the whole session finishes, not per section.
- Exam highlights/strike-outs are device-local; scratch ink persists (reviewable after finish).
- No "comfortable pass" line on the trend chart (no validated estimate); the official weights overlay replaces it.
